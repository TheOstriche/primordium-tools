# Primordium World Map

A laptop web app with one job: **building out and improving the Primordium world map at high detail and scale**. It draws the map from data and edits that data. Notes for the owner in `README.md`; how it fits with the other apps in `../ARCHITECTURE.md`; the owner's notes and open world decisions in `docs/map-notes.md`.

## Rules for working here
- **Never invent names or lore.** Settlements stay unnamed until the owner names them. Region names, realm borders, and landform explanations come from the owner through the Claude project (as handoff answers; see `../exports/handoff/map.md`, written by `node tools/export-handoffs.js`). Until the owner decides the open world decisions in `docs/map-notes.md`, keep the map as it is and build the tools that make the fixes easy.
- **The map is one data file:** `../shared/map/primordium-map.json`. `../shared/map/map-data.js` is generated from it (the app's Save, or `node tools/build-map.js`); never edit it by hand. `node tools/build-map.js --apply changes.json` applies a handoff answer.
- **The rules of the data live in `../shared/map/map-model.js`** (`PrimordiumMap`), with no screen code, and are tested by `tools/test-map.js`: the format (`KINDS`, `TYPES`), the gate for outside data (`shaped`), the checks (`check`), what is under a point (`hit`), comparing and patching (`diff`, `patch`), and the file text (`serialize`, `dataFile`). Put new data rules there with a test, not in the app.
- **Stored data stays plain; detail is generated when drawing** (`js/draw.js`), seeded from each feature's id so it never shifts. Don't store generated detail (tree positions, peak shapes) in the map.
- No build step and no ES modules: the app opens from a double-clicked `index.html`. Each file in `js/` is wrapped in a function and sets one global, loaded in this order: `ui.js` (`MapUI`) → `draw.js` (`MapDraw`) → `terrain.js` (`MapTerrain`) → `view.js` (`MapView`) → `store.js` (`MapStore`) → `editor.js` (`MapEditor`) → `panels.js` (`MapPanels`) → `app.js`.
- **Every change to the map goes through `MapStore`** (`edit(fn)`, or `begin()`/`touch()`/`end()` for a drag), so it can be undone, is kept as a draft, and redraws the right layers. Look features up by id inside the edit; after an undo the map is a new object.
- **Anything from outside goes through `PrimordiumMap.shaped()`** (the data file, the draft, an opened file, pasted changes), and text is escaped when drawn (`MapDraw.esc`) or added as text nodes (`MapUI.h`).
- **Drawing:** `draw.js` is a stack of SVG layers (`LAYERS`), each naming the lists it reads; a layer is redrawn only when those change. No SVG filters (they redraw slowly while panning). Sizes that should stay readable when zoomed (icons, line widths) use the `--s` variable through `sw()`, `dashed()`, and `at()`; export bakes them in (`ctx.flat`).
- **The land is a painted picture** (`terrain.js`), not vector shapes: terrain areas blend into each other along ragged, soft edges, with two or three tones mixed by map-anchored noise, rocky ground under ranges, a strand along shores, and small marks (dunes, tufts, reeds, cracks). The whole map is painted once; when zoomed in, only the part on screen is painted again at screen sharpness, with finer texture and marks (that is how detail appears with zoom). Painting runs in short bursts so the page never freezes, and a newer request cancels an older one. A new terrain type needs an entry in `PAL.terrain` (and in `TYPES` in `map-model.js`); a new mark needs a case in `mark()`.
- **Generated life:** besides woods, `draw.js` draws rolling hills over `hills` areas, copses on open country, and a ship off each port; `terrain.js` paints tilled fields round settlements on farmable ground. All of it is worked out from the data and seeded, never stored. To make a region hilly, add a `hills` terrain area.
- **Roads, paths, villages:** a road joins two settlements and bends through its `via` points; a path (`paths`) is a free line for side tracks, with one end on a road, settlement or path. `village` is a settlement type shown only from `lod2`. Bridges are drawn where a road crosses a river (`bridges()` in `draw.js`), never stored. The current roads, paths and villages were laid by one-off scripts (2026-11-13); nothing reroutes them automatically when the map changes.
- **Rivers run downhill by hand:** one outlet per lake, no river splits, none crosses a range. Nothing checks this yet (there is no elevation); keep to it when editing.
- **Borders follow one rule** (checked in `map-model.js`): a border is a closed loop, or each end reaches the sea or another border. They are drawn on land only, so the coast finishes a coastal territory's outline.
- **Looking and editing are separate modes** (`MapEditor.setEditing`). Looking (the default, and what a visitor to the published site gets) only selects, pans, zooms, searches and measures, and shows a read-only card. Editing shows handles, the form, Add, Undo and Save. Anything that changes the map must check `editing`.
- **The page is a full-window map with floating controls** (search, tools, panels, zoom, a live scale bar). The address always holds the view (`#x=…&y=…&z=…`), so a link opens the same spot. Zooming glides (`MapView`: `goal` is where the view is heading, `vb` where it is). Detail levels are the `lod0`–`lod3` classes set by `view.js` and used by `STYLE` in `draw.js`.
- **Colors:** the app around the map uses theme tokens (`../shared/theme.css`), never fixed colors, and is checked in light and dark. The map artwork's own colors are the one exception: they live in `PAL` at the top of `js/draw.js` (terrain included, under `PAL.terrain`) and nowhere else.
- Laptop first for editing (mouse and keyboard). Looking also works on a phone: pinch to zoom, panels become sheets along the bottom.
- Run `node tools/test.js` from the repository root after any change.

## Status (2026-11-12)
Built: the renderer with painted, blended terrain and zoom-dependent detail; the full-window interface (search, hover names, read-only cards, links to a view, live scale bar, phone layout); the editor (select, reshape, draw every kind of feature, bend roads, reorder terrain); undo and redo; the feature list, layers, and checks; measuring; saving into the project folder; opening and downloading the map file; copying and applying changes in the handoff shape; and PNG and SVG export.

Terrain types the map can draw but does not use yet (the owner or the Claude project decides where, if anywhere): hills, scrub, savanna, farmland, marsh, jungle, badlands, snow.

Not built yet (the owner sets the order): travel times once a scale is set, regional and local maps linked from the world map, an elevation layer with river-runs-downhill checks, wind and rain-shadow overlays, region tags tied to NPC families, and using the map inside the GM tool and Codex.

## Tool defaults the owner may change (not lore)
- Small towns, minor roads, and labels under size 16 are hidden until zoomed in (`view.js`, `STYLE` in `draw.js`); the Layers tab can turn this off.
- A settlement counts as on land, and a river as reaching water, within 5 map units of the shore (`NEAR` in `map-model.js`), because the drawn coast is roughened and the map was traced by hand.
- The artwork: palette, terrain tones and marks, how wide and ragged terrain edges are (`feather`, `rough`), shallow-water bands, tree and peak shapes, icons, the border line (`js/draw.js`, `js/terrain.js`).
- The map opens in looking mode unless editing was on last time or there are unsaved edits (`app.js`).
