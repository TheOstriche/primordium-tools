# How Primordium Tools fits together

Four static web apps for the Primordium 2.0 tabletop RPG, published together with GitHub Pages. There is **no build step**: every file is served as written, so what you read is what runs. This page explains where things live, how the pieces connect, and why they are arranged this way. For publishing and day-to-day editing, see `README.md`.

## The apps

| Folder | Who uses it | On | What it does |
|---|---|---|---|
| `sheet/` | players | phone, installable, works offline | A character sheet: HP, stats, effects, gear, skills, dice, and the tactical deck. |
| `codex/` | everyone | phone, installable, works offline | A rules reference: search, skills, bestiary, rules and tables, dice tray, deck simulator. |
| `gm/` | the GM | laptop, opens from a double-clicked file | Encounters, a grid map, initiative, enemy turns, HP, stacks, XP, shops. |
| `map/` | the GM (worldbuilding) | laptop, opens from a double-clicked file | The world map: a detailed, zoomable drawing of the map data, and the editor for building it out. |
| `index.html` | | | The front page linking all four. |

## Shared code (`shared/`)

Everything more than one app needs lives here, once. Each file sets one global (no modules, so the GM tool can open from `file://`). Files marked *Node* also load in the tests.

| File | Global | What it holds | Used by |
|---|---|---|---|
| `core.js` (*Node*) | `PrimordiumCore` | The game's rule tables and small helpers: rarities, stats, the D20 tactics table, cooldowns, roles and XP, stacks and recovery, movement; `esc`, `slug`, `signed`, `plural`. | all |
| `primordium-data.js` | `PRIMORDIUM_DATA` | Every skill (tiers, paths, abilities, perks), race stats and specials, background traits. Generated from the owner's working sheets. | all |
| `items-data.js` | `PRIMORDIUM_ITEMS` | Items: materials, gear and its prices by tier, Condition and armor rules, consumables, selling and Haggler, which tiers shops stock by level, and the GM tool's shop defaults (shop types, quantities). | all |
| `items.js` (*Node*) | `PrimordiumItems` | Item rules from that data: names, Condition, armor, prices, sell offers, Auto-fill, a bought item as a sheet item, and packing a shop into a link. Also the Codex's Prices and Condition rows. | all |
| `qr.js` (*Node*) | `PrimordiumQR` | QR codes (written here, no library): the GM tool shows a shop's link as one. | GM |
| `npc-data.js` | `PRIMORDIUM_NPCS` | Every creature from the NPC Guide (165 in 38 families). | Codex, GM |
| `character-rules.js` | `PrimordiumCharacter` | What a character's skills grant, and their stats, max HP, and armor. The sheet shows these; the GM tool imports sheet backups with the same code, so the two always agree. | sheet, GM |
| `tactics-deck.js` | `PrimordiumDeck` | The tactical deck: builds the 52 cards and jokers from a Tactics level, runs a hand with every Tactics mechanic, and draws it (its HTML is shared too). | sheet, Codex |
| `dice.js` | `PrimordiumDice` | Rolling `2D6+3`-style expressions, and the dice tray buttons. | sheet, Codex |
| `fx.js` | `PrimordiumFX` | Impact effects (purely for feel): card plays from Rare to Mythic, crits and natural 1s, HP, combat, rests; and the effects settings. | all |
| `theme.css` | | The look: color tokens for dark and light, fonts, and shared components (buttons, segmented choices, rarity chips, panels, tables, toasts, dice tray, deck). | all |
| `theme.js` | `PrimordiumTheme` | Light/dark: follows the device by default; any `<button data-theme-toggle>` cycles System → Light → Dark. | all |
| `map/primordium-map.json` | | The world map as data: coastlines, terrain areas, ranges, rivers, lakes, borders, settlements, roads, labels. The source of truth for the map; its format is in `exports/handoff/map.md`. | map (GM and Codex later) |
| `map/map-data.js` | `PRIMORDIUM_MAP` | The same map packaged so a page opened from a file can load it. Generated by the map app's Save or `node tools/build-map.js`; never edited by hand. | map |
| `map/map-model.js` (*Node*) | `PrimordiumMap` | The rules of the map data, with no drawing: the gate for outside data (`shaped`), the checks (`check`), what is under a point (`hit`), comparing and patching maps, and the exact text of the two files above. | map |
| `offline.js` | `primordiumOffline()` | The service-worker logic both phone apps use (`sheet/sw.js`, `codex/sw.js` call it). | sheet, Codex |

### How the data flows

```
Owner's guides and working sheets
  ├─ shared/primordium-data.js, shared/npc-data.js   (generated; edit to change game data)
  ├─ shared/core.js                                   (rule tables, hand-written)
  ├─ shared/items-data.js                             (materials, gear, prices, consumables, shop stock)
  ├─ codex/codex-data.js                              (rules text, tables, race lore: Codex only)
  └─ gm/docs/*.md, gm/data/scaling.json               (GM rulings, scaling workbook: GM only;
                                                        `node gm/tools/build-data.js` turns them into gm/data/*.js)
  └─ shared/map/primordium-map.json                   (the world map; the map app edits it, and its Save or
                                                        `node tools/build-map.js` writes shared/map/map-data.js)
        ↓
  core.js → items-data.js → items.js → character-rules.js / tactics-deck.js / dice.js / fx.js → each app's own files
```

## Inside each app

Every app follows the same shape: an `index.html` that loads the theme in `<head>`, then the shared scripts, then its own scripts **in order**. Each app's own files are plain scripts that share one scope, so a name declared in an earlier file (say `state` or `esc`) is available to the later ones. Each file starts with a comment saying what it holds.

| | Codex (`codex/js/`) | Sheet (`sheet/js/`) | GM tool (`gm/js/`) |
|---|---|---|---|
| Data and saving | `data.js`: shapes the shared data, builds the search index | `store.js`: saving, new characters, upgrading old saves, what is on screen | `store.js` (IndexedDB, backups), `data.js` (creature lookup) |
| Rules | (in the shared files) | `rules.js`: totals, stacks, the deck | `rules.js` (scaling math), `combat-engine.js`, `skills.js`: no screen code, tested |
| Helpers | `ui.js`: chips, dice in text, the roll toast | `ui.js`: toasts, fields, the dice tray log | `ui.js` (`h()` element builder), `markdown.js` |
| Screens | `views.js`: one function per screen | `views.js` (tabs), `sheets.js` (bottom sheets), `shop.js` (a shop from the GM's link) | one file per tab: `encounter.js`, `combat-view.js`, `grid.js`, `reference.js`, `creatures.js`, `shops.js`, `save-view.js` |
| Events | `app.js`: state, navigation, a table of taps | `app.js`: actions, a table of taps, forms, the ⋯ menu | each tab file wires its own; `app.js` switches tabs |
| Its own look | `style.css` | `style.css` | `css/style.css` |

The map app (`map/js/`) is the newest and wraps each file in its own function that sets one global, loaded in this order: `ui.js` (`MapUI`: elements, menus, dialogs), `draw.js` (`MapDraw`: the map as layered SVG; generated detail and the artwork's colors), `terrain.js` (`MapTerrain`: the land painted as a picture, with terrain areas blended into each other and more detail as you zoom in), `view.js` (`MapView`: pan, gliding zoom, level of detail), `store.js` (`MapStore`: the map being edited, undo, drafts, saving into the project folder), `editor.js` (`MapEditor`: looking and editing modes, selecting, reshaping, drawing, measuring), `panels.js` (`MapPanels`: search, the feature list, layers, checks, and the details panel), `app.js` (the floating controls, links to a view, saving, export).

The Codex and sheet draw screens as HTML strings and redraw on each change; a tap is matched against a table (`TAPS`) of `data-*` attributes, which makes it easy to find what a button does: search for its attribute. The GM tool builds elements with `UI.h()` and wires events where it builds them.

## Saved data

All apps are on one site, so they share browser storage. Each uses its own keys:

| Key | App | Holds |
|---|---|---|
| localStorage `primordium.characters.v1` | sheet | every character, `{ id: character }` (also the backup file format the GM tool imports) |
| localStorage `codex:*` | Codex | last tab, tactics level, roll history, deck (safe to clear) |
| IndexedDB `primordium-gm`, localStorage `gm-tab` | GM | players, encounters, custom NPC types, shops, the combat in progress, map images |
| localStorage `primordium.map.draft.v1`, `primordium.map.prefs.v1`; IndexedDB `primordium-map` | map | unsaved map edits (cleared by Save), which layers are shown, and the remembered map folder |
| localStorage `primordium.theme`, `primordium.fx` | all (shared on purpose) | light/dark choice, effects settings |
| caches `primordium-v*`, `codex-v*` | sheet, Codex | offline copies; each app only clears its own |

## Why it is built this way

- **No build step, plain scripts.** The owner edits and publishes with GitHub Desktop; nothing to install or compile, and the GM tool still opens from a double-clicked file (which rules out ES modules).
- **One copy of every rule and table.** Before this review the rarity list existed six times and the tactics table twice. Now a number changes in one place (`shared/core.js` or the data files) and every app follows; `node tools/test.js` checks they still agree (for example, the scaling workbook's XP multipliers against the core).
- **One look.** The Codex's styling is the house style. `shared/theme.css` holds the tokens and components; an app's stylesheet only lays out its own screens. Colors are always tokens (`var(--glow)`, `var(--r-rare)`), never fixed values, so light mode works everywhere.
- **Shops travel in the link.** A shop link (`sheet/#shop=…`) carries the whole shop, compressed: item names, tiers, materials, quantities, and custom items. Nothing is uploaded and no server is needed; the sheet works out prices and Condition from `shared/items-data.js`. The GM tool's stock is not changed by purchases (the player tells the GM).
- **Outside input is checked where it comes in.** Three things arrive from outside: shop links, sheet backup files, and GM backup files. Each has one gate (`PrimordiumItems.decodeShop`, `adopt()` in `sheet/js/store.js`, `shaped()` in `gm/js/store.js`; map files and pasted map changes go through `PrimordiumMap.shaped()`) that forces every value into a known shape, so the rest of the code can trust what it holds. The phone apps also carry a Content-Security-Policy that only lets this site's own script files run.
- **Saved data is guarded.** Both stores write at once when the page is hidden, report a failed save instead of hiding it, and ask the browser for persistent storage. The sheet keeps unreadable data aside rather than writing over it and follows changes made in another tab; the GM tool restores a backup all-or-nothing and warns when it is open in two tabs.
- **Offline: network first, saved copy as fallback.** `shared/offline.js` takes the network's answer when it comes within a few seconds and the saved copy otherwise; it never saves an error page over a working file.
- **The map is data; its detail is drawn.** The stored map is plain outlines, lines and points. Roughened coasts, shallow-water bands, trees, peaks and tapered rivers are generated when drawing, seeded from each feature's id so the picture never shifts. The drawing is a stack of layers, each redrawn only when the lists it reads change, and it uses no SVG filters (they redraw slowly while panning). The land is the one painted layer: `terrain.js` blends terrain areas along soft, ragged edges using noise anchored to the map, paints the whole map once, and repaints just the part on screen at screen sharpness when zoomed in, in short bursts so the page stays responsive. Clicks are worked out from the data (`PrimordiumMap.hit`), not from the drawing, so they can be tested.
- **The map saves into the project.** A web page cannot write to disk on its own, so the map app asks once for the `shared/map` folder (the File System Access API in Chrome and Edge) and then writes `primordium-map.json` and `map-data.js` there, one feature per line so GitHub Desktop shows exactly what changed. Until Save, edits are kept as a draft in the browser. If the file in the folder is not the one the page started from, Save asks before replacing it.
- **Effects are separate from rules.** `fx.js` never changes a number. The deck engine reports what happened (`act()` returns `{ played, drawn }`) and the apps decide how to show it.

## Changing things safely

- **Game data:** edit `shared/primordium-data.js` or `shared/npc-data.js`; rule tables: `shared/core.js`. Run `node tools/test.js`.
- **A phone app's files (or anything in `shared/` it loads):** run `node tools/stamp-offline.js`. It raises the version in the app's `sw.js` and records a fingerprint of the cached files, so installed phones update; keep the file list there matching what its `index.html` loads. The tests fail if the version was not raised or a loaded file is not listed.
- **The world map:** edit it in the map app and press Save, or replace `shared/map/primordium-map.json` and run `node tools/build-map.js`. `node tools/test.js` checks the map (unique ids, roads join real settlements, settlements on land, rivers reach water) and that the packaged copy matches.
- **A new screen or button:** follow the app's pattern: a view function in `views.js`, a `data-*` attribute on the button, an entry in `TAPS` in `app.js`.
- **New colors or components:** add tokens or components to `shared/theme.css` if more than one app could use them.
- **Tests:** `node tools/test.js` runs every suite (the project itself: scripts parse, pages load real files, offline lists and versions; shared core, character rules, stored data, tactical deck, items and shops (including QR codes), the world map, GM game math, GM combat rules, and the Codex guide parser if Python is installed). `tools/test-data.js` checks the data files agree with each other and that every perk the code reads by name (from `tools/lib/data-links.js`) still exists.
- **Handoffs:** `node tools/export-handoffs.js` writes `exports/handoff/`, one Markdown file per kind of stored data (format, rules, current contents, how to bring a change in), for a Claude project. Run it again after any data change. Then try the apps with `node tools/serve.js` at http://localhost:8080 on a phone-sized window, in light and dark.
